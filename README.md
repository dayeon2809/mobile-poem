# 몸의 시 — 독립 모바일 웹앱

기존 전시 코드와 별도로 실행합니다. TD, OSC, 전시장 내부 IP에 의존하지 않습니다.

**공통 QR → `/` 모바일 설문 → `POST /api/poems` → 시 생성 및 Google Sheets 저장 → `/poem.html?id=개별UUID`**

기존 `public/sketch.js`의 감정과 질문 8개를 가져왔습니다. 캔버스 대신 HTML 버튼과 입력창을 사용해 작은 화면, 스크롤, 화면 회전, 모바일 키보드를 지원합니다. 질문 문구는 `public/questions.json`, 디자인은 `public/style.css`, 생성 프롬프트는 `app-core.js`에서 수정합니다.

원본의 `rgb(10, 5, 20)` 배경, 별 200개와 마우스 입자, 원형 감정 배치와 초록색 선택 표시, 파란 버튼, 포스터를 반영했습니다. 배경 효과는 `public/space.js`에서 그리며 모바일에서는 원형 배치가 화면 폭에 맞춰 줄어듭니다. 모션 감소 설정에서는 애니메이션을 멈춥니다.

**처음 배포한다면 [Vercel 배포 안내](DEPLOY.md)를 따라 진행하세요.** 저장소 구성, 시트 준비, 환경변수 입력, QR에 넣을 주소까지 설명합니다.

## 준비 및 실행

1. Node.js 22 이상에서 이 폴더를 작업 디렉터리로 사용합니다.
2. `npm install`을 실행합니다.
3. `.env.example`을 `.env`로 복사하고 실제 값을 설정합니다. 상위 전시용 `.env`는 자동으로 읽지 않습니다.
4. 사용할 Google 스프레드시트를 `GCP_CLIENT_EMAIL` 서비스 계정에 편집자로 공유합니다.
5. **빈 탭 `mobile_poems`를 새로 만듭니다.** 기존 `test1` 탭은 사용하지 마세요. 첫 행에 아래 열 이름을 넣습니다.

| A | B | C | D | E | F |
|---|---|---|---|---|---|
| id | timestamp | name | emotions | answers | poem |

6. `npm start` 실행 후 `http://localhost:3100`을 엽니다.

`emotions`와 `answers`는 JSON 문자열입니다. 저장 시 RAW 모드를 사용합니다. 생성 또는 저장이 실패하면 화면에 오류를 표시하고 재시도할 수 있습니다. 서버에 저장된 동일 ID로 다시 제출하면 기존 결과를 반환합니다. 질문 응답은 현재 탭의 sessionStorage에 보관하며 결과를 확인하면 지웁니다.

## 공개 접속과 QR

- 이 폴더를 Vercel의 Express 프로젝트로 배포합니다. `server.js`가 앱을 export하며, Build Command와 Output Directory를 별도로 지정하지 않습니다.
- Vercel에 `.env.example`의 서버 환경변수를 등록합니다. Vercel에서는 `PORT` 설정이 필요 없으며, 로컬에서는 `npm start`로 실행합니다.
- **공개 HTTPS 주소**를 사용합니다. 예를 들어 운영 주소가 `https://your-domain.example`이면, 참여용 QR에는 `https://your-domain.example/`를 넣습니다. 이 주소는 예시이며 실제 배포 주소가 아닙니다.
- API는 모두 상대 경로라 공개 도메인으로 바꾸어도 프런트엔드 코드 변경이 필요 없습니다. 프런트엔드와 API를 같은 서비스에 배포해야 합니다.
- 개인 결과는 서버에서 돌려준 `/poem.html?id=...`로 연결됩니다. 결과 화면에서 링크를 복사할 수 있습니다. 결과 링크는 그 시의 열람 권한과 같으므로 원하는 사람에게만 공유합니다.
- 공개 주소가 정해진 뒤 그 주소로 참여용 QR 이미지를 생성하고, 전시장 Wi-Fi를 끈 휴대폰에서도 시작부터 결과 열람까지 확인합니다.

## 기존 파일과의 관계

기존 `server_test.js`, `server_exhibit.js`, `sheet_server.js`, `public/`, 루트의 `poem.html`은 수정하지 않았습니다. 기존 루트 `poem.html`은 최근 시 목록을 보여주는 전시 화면입니다. 새 `public/poem.html`은 한 참여자의 결과만 표시하며 기존 전시 목록과 자동 연동하지 않습니다.

OpenAI API 키는 서버에만 둡니다. 시 생성은 [공식 Chat Completions API](https://platform.openai.com/docs/api-reference/chat/create)를 사용하고 모델은 `OPENAI_MODEL`로 지정합니다. 기본값의 실제 사용 권한과 비용은 운영 API 프로젝트에서 확인해야 합니다.

## 검증과 운영 범위

`npm test`는 외부 API를 호출하거나 실제 시트에 쓰지 않고 참여자 분리, 중복 제출, 오류 후 재시도, 입력 검증, 결과 조회를 확인합니다. 실제 키를 사용한 시 생성·시트 저장 및 공개 배포 검증은 별도입니다.

소규모 참여를 위한 구현입니다. Vercel은 여러 인스턴스를 자동 실행할 수 있습니다. 시트 조회는 탭을 읽어 ID를 찾고, 동시 생성은 서버당 최대 10개로 제한합니다. 여러 서버 인스턴스 사이의 중복 제출 잠금은 제공하지 않습니다. 대규모 공개 운영에는 데이터베이스의 고유 키, 작업 큐 및 요청 제한을 추가해야 합니다. 시 생성에 성공했지만 저장이 실패하면 재시도 시 시가 다시 생성될 수 있습니다.


## 시와 QR 전시 화면

`/gallery.html`에서 최근 10편을 시·별명·QR 카드로 표시하며 15초마다 갱신합니다. QR은 해당 시의 `/poem.html?id=...` 개인 페이지를 엽니다. 기존 저장 데이터도 즉시 표시하고 QR을 생성합니다.

새 응답부터 G열에는 `resultUrl`, H열에는 `qrUrl`을 저장합니다. 기존 A:F 데이터 형식은 유지합니다. 첫 행 G1/H1에 위 열 이름을 추가할 수 있습니다. 이전 행의 G/H는 자동으로 변경하지 않지만 전시 API가 ID로 링크를 계산하므로 기존 시도 정상 표시됩니다.

QR의 공개 도메인은 Vercel의 `VERCEL_PROJECT_PRODUCTION_URL`을 자동 사용합니다. 다른 도메인을 쓰려면 `PUBLIC_BASE_URL=https://mobile-poem-psi.vercel.app`처럼 설정한 뒤 재배포하세요. Preview에서도 QR은 Production을 가리키므로 시가 Production과 같은 저장소에 있어야 합니다.

전시 API는 시·별명·작성 시각·결과 링크만 공개하며 원본 질문 응답은 반환하지 않습니다. 참여 화면에 전시 공개 안내를 추가했습니다. QR은 서버에서 PNG로 직접 생성하며 외부 QR 서비스에 링크를 전달하지 않습니다.

전시 화면은 데스크톱에서 카드 3개를 나란히 배치하고, 4편 이상이면 천천히 좌우로 자동 이동합니다. 카드에 부유 효과를 적용하며 마우스를 올리거나 키보드로 카드에 진입하면 멈춥니다. 움직임 정지 및 이전/다음 버튼도 제공합니다. 모바일은 가독성을 위해 한 편씩 표시합니다. 시트 갱신 시 기존 카드와 읽던 위치를 유지합니다.
